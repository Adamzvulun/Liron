# Security review: 2026-11-04

A read-only review of `dev` at `374bc79` (after PR #86), done by a security-focused agent at Adam's request ("check everything we've done so far"). Each write-path finding was reproduced against the real migrations in PGlite before it was fixed.

**Threat model:** sign-ups are invite-only (ADR 0016) and Adam is the only user today. The publishable key is public by design, so any signed-in account can call any table or function it's granted, not only the ones the UI uses. The High items become serious once friends join (M5), or if sign-ups or anonymous sign-ins are ever switched on.

## Findings and status

| # | Finding | Status |
|---|---|---|
| H1 | A signed-in user could write their own wallet, XP, streak and progress straight through the Data API | **Fixed** by [ADR 0029](../../decisions/0029-database-is-the-only-writer-of-rewards.md): only database functions write them |
| H2 | The pay-once daily chest could be claimed again by resetting `goal_reached` | **Fixed:** each chest is a row in `daily_chests` |
| H3 | `record_progress` took any subject, 10,000 XP per call, and a changed time zone made a second "today" | **Fixed:** known subjects only, 3,000 XP a day, time zone changes at most every 20 hours |
| H4 | The licensed deck was readable by any signed-in account, including an anonymous one | **Fixed:** licensees only, anonymous refused |
| M1 | Repository secrets (including prod's) can be read by a workflow on **any** pushed branch, not only `dev` and `main` | **Accepted by Adam** (2026-11-04): only Adam pushes to this repo. Claude's cloud sessions push branches under his account, so they count as him. The ADR text claiming otherwise is corrected |
| M2 | The content upload job runs `npm ci` with the secret key in its environment | **Fixed** in #95 |
| M3 | No security headers or CSP; the session token sits in `localStorage`. No exploitable XSS was found | **Fixed:** `vercel.json` sends a strict CSP (scripts and styles from our own site only, no inline styles or eval; Supabase the only outside host), plus nosniff, `X-Frame-Options: DENY`, a referrer policy, a permissions policy (microphone on our site only) and HSTS. `e2e/headers.spec.ts` serves the app with those exact headers and fails on any violation. It caught two: zod's eval probe (off with `jitless`) and the city painter's inline `style` attributes (now CSS classes) |
| M4 | The recorder can leave the microphone open (double start, or a failure after the mic opened) | **Fixed** in #90. The "stays local" claim holds: nothing uploads the recording |
| L1 | Signed audio links last an hour and are cached past expiry (audio fails silently after an hour) | **Fixed** in #95: 10-minute links, renewed |
| L2 | `mediaUrl` isn't bound to the subject | **Fixed:** it only links files named in a pack this subject has loaded |
| L3 | The bucket migration could leave a hand-made public bucket public | **Fixed:** the migration sets `public = false` |
| L4 | Unbounded JSON a user can write | **Partly fixed:** avatar < 4 KB, state < 64 KB. Review cards and logs remain |
| L5 | Sign-out is local only | **Not a gap** (checked 2026-11-04): `signOut({ scope: 'local' })` calls the server's `/logout?scope=local`, which revokes this device's refresh token (`@supabase/auth-js` `GoTrueClient._signOut` → `admin.signOut`). Only the access token lives on until it expires (about an hour), whatever the scope. "Sign out everywhere" stays an idea, not a fix |
| L6 | Small pipeline guards (an empty `not in` list) | **Fixed:** lesson ids must be plain ids, and an empty list deletes the source's lessons without a filter |

## Verified OK
- No secrets in the working tree, the git history or the build.
- The secret key never reaches the browser; the deck's text and audio aren't in the bundle.
- Every table has row-level security; users can't see each other's rows.
- Every function sets `search_path = ''` and refuses a missing user.
- The browser can't write to the private bucket.
- CI actions are pinned by commit, and pull requests get no secrets.

## M1: options for Adam
1. **GitHub Environments with a branch rule.** Needs a paid GitHub plan for a private repo. **Costs money.**
2. **Keep prod's secrets out of GitHub.** Prod migrations and the deck upload would run by hand at release, from a computer you trust.
3. **Accept the risk**, knowing anyone who can push a branch can reach prod's keys, and keep push access to you and Claude.

## The Groq speech check, designed safely
Adam approved it on 2026-11-04. It needs its own ADR before it's built:
- One Vercel function holds `GROQ_API_KEY` (no `VITE_` prefix, never in GitHub, separate dev and prod keys).
- It verifies the Supabase session, refuses anonymous users and non-licensees.
- Daily and per-minute limits are kept in a table the browser can't write.
- It checks size, length and type, and fixes the model, language and prompt on the server.
- It stores and logs no audio, and returns only the transcript and "understood".
- It's opt-in, with a notice that the clip goes to Groq. M4 is fixed first.
